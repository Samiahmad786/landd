# Bhumi Saathi — Flutter Android starter

Independent land-services companion for India. Not affiliated with any government body.

## Stack
Flutter stable, Dart, Riverpod, go_router, ARB localization, Firebase packages, Remote Config package, webview_flutter, Material 3.

## Included in this starter
- Nine-language selection with saved locale preference.
- State → district selectors and state-specific service terminology.
- JSON-driven state, portal and sample unit configuration.
- Dashboard cards for records, village maps, plot search, mutation, revenue and offices.
- In-app WebView with progress, retry/error message and official-source disclaimer.
- Area calculator with baseline acre/decimal/sq-ft/sq-meter conversions.
- GitHub Actions workflow for debug/release APK artifacts and release on version tags.
- Footer: Developed by Sami Sajjad.

## Important implementation boundaries
- The included state/district data is a partial sample, not a verified complete current India master. Add and periodically verify all State/UT district lists from official sources.
- Portal URLs are entry points only. Bhumi Saathi does not fetch land records from a backend. Portal OTP/CAPTCHA and terms remain under the official portal; no bypass is implemented.
- Bihar Katha/Dhur sample factors are illustrative only. Local values vary by district/locality. UP Gaj is represented as square yard (9 sq ft), not a district-specific revenue conversion. Never use demo values for legal/financial decisions.
- Firebase dependencies are included, but this starter's login screen is not wired to live Firebase. Real Phone OTP, Email auth, Firestore profile, and Remote Config require a Firebase project, Android app registration, provider enablement, SHA fingerprints and security rules. Do not commit `google-services.json` or service account keys.
- Release APK generated by workflow is not production-signed. Configure a private upload keystore and GitHub secrets before Play Store distribution.

## Build
GitHub Actions generates Android platform scaffolding using `flutter create`, then runs `flutter pub get`, `flutter gen-l10n`, `flutter analyze`, `flutter test`, and builds debug and release APKs.
Locally: install Flutter stable + Android SDK, then run:
`flutter create --platforms=android --org com.bhumisaathi .`
`flutter pub get`
`flutter gen-l10n`
`flutter run`
`flutter build apk --debug`

## Firebase activation
1. Create Firebase project and register Android package `com.bhumisaathi.app`.
2. Add `google-services.json` privately under `android/app/`; add it to `.gitignore`.
3. Run FlutterFire CLI configuration and initialize Firebase in `main.dart`.
4. Enable Phone and Email/Password sign-in; configure SHA-1/SHA-256, test numbers, SMS region policy and quotas.
5. Implement OTP verification, Firestore profile creation, Remote Config fetch/activate and account deletion with server-side security rules.

## Signing and Play Store
Create a private keystore locally with `keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`. Never commit the keystore or passwords. Add GitHub secrets and Gradle signing configuration before producing a production release.
For Play Store use `flutter build appbundle --release`, then prepare adaptive icon, splash, privacy policy URL, Data Safety, content rating, target audience, account deletion and non-government-affiliation wording.
